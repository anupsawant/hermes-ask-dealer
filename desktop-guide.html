01What the desktop app is

The desktop app is the product the Ask Dealer fork ships, branded Gideon. It is its own native chat surface. It doesn't embed the browser dashboard or the terminal UI; it has its own composer, transcript and slash-command pipeline. The agent itself runs in a Python child process (hermes serve) that the app spawns and talks to over HTTP and WebSocket.

PartyAuthoritative forCode
Electron mainThe machine: process lifecycle, backend spawn and pool, native fs/git/terminal/windows, install and update, secrets (safeStorage), a narrow typed capability bridgeelectron/
RendererThe experience: navigation, presentation, short-lived interaction statesrc/
BackendThe work: sessions, tools, model calls, streaming, config, cronPython hermes serve, one per (connection, profile)

Decide state by authority: anything another Hermes surface can change belongs to the backend (the renderer holds a cache); machine and runtime facts belong to Electron; only this window's presentation belongs to the renderer.

declare const __HERMES_PRODUCT_IDENTITY__: ProductIdentity

/** The baked identity of this artifact (dev bundles derive it live). */
export const PRODUCT_IDENTITY: Readonly<ProductIdentity> =
  typeof __HERMES_PRODUCT_IDENTITY__ === 'undefined'
    ? Object.freeze(nodeCreateRequire(import.meta.url)('../product-identity.cjs') as ProductIdentity)
    : Object.freeze(__HERMES_PRODUCT_IDENTITY__)

export function applyDesktopIdentity(app, identity = PRODUCT_IDENTITY): string | null {
  if (!identity.token && identity.appNamePascal === identity.artifactNamePascal) {
    return null
  }
  const userData: string = path.join(app.getPath('appData'), identity.appNamePascal)
  mkdirSync(userData, { recursive: true })
  app.setPath('userData', userData)
  app.setName(identity.displayName)
  return identity.displayName
}

export function resolveUpdaterMechanism(facts: MechanismFacts): UpdaterMechanism {
  if (facts.source === 'commit-build') { return 'external' }
  if (facts.updateMechanism && facts.updateMechanism !== 'self') { return facts.updateMechanism }
  return facts.platform === 'win32' ? 'windows-handoff' : 'posix-handoff'
}

export function persistentAtom<T>(key: string, fallback: T, codec: Codec<T> = Codecs.json<T>()): WritableAtom<T> {
  const raw = readKey(key)
  let initial = fallback
  if (raw !== null) { try { initial = codec.decode(raw) } catch { initial = fallback } }
  const $value = atom<T>(initial)
  // Persist CHANGES only — never the creation-time value.
  let creationEmission = true
  $value.subscribe(value => {
    if (creationEmission) { creationEmission = false; return }
    writeKey(key, codec.encode(value))
  })
  return $value
}

24Design system

DESIGN.md is the visual and interaction contract. Rule of thumb: one source per concern, tokens over literals, flat over boxed. Named contracts (tokens, Button variants, primitive names) must change in DESIGN.md in the same commit.

Principles

  1. Flat, not boxed: no card-in-card.
  2. Floating panels use borderless elevation: shadow-nous + --stroke-nous.
  3. One primitive per concern.
  4. Tokens, not literals: never bg-white or border-gray-*.
  5. Style lives in the primitive: call sites pass variant/size, not padding or radius classes.
  6. Intent before automation: never open panes, move focus or navigate because something happened in the background.
  7. Immediate feedback: paint first, persist after, roll back visibly.

Information architecture

Chat is home. Pages are durable destinations (Chat, Skills, Messaging, Artifacts). Route overlays are short tasks (Settings, Command Center, Cron, Profiles, Agents, Starmap). Panes are working context. One action, one home.

Rules that come up often

  • Text buttons are square; only icon buttons have a 4 px radius.
  • No native title= on buttons (a test enforces it); tooltips only when hover teaches something.

31Engineering principles

From ENGINEERING.md and AGENTS.md, with the reasons behind them.

Identity is not incidental

Sessions have durable, runtime and lineage-root ids. Conflating them causes "session not found" and vanishing history. prompt.submit writes the session and user rows before the turn so a crash still leaves a resumable transcript.

Server truth is cached, not owned

Merge, don't clobber. Paint optimistically and roll back visibly. Guard against stale async results with generation counters. Only the foreground surface publishes into the shared view. Keep reference identity on no-ops.

Switching is a re-home, not a reboot

Connection apply = soft re-home (wipe gateway-bound stores, reconnect). HERMES_HOME change = hard reload. Profile swap = merge lists. Afterwards the socket, profile and connection atoms must agree.

Cross everything as an observable ladder

One resolver per policy; precedence as data; candidates trusted only after probing; a failed read falls to the next rung, a failed write surfaces or rolls back; retries bounded and ending in a recovery affordance.

Guest content opens nothing

Window opens are denied; only trusted clicks in the preview partition reach the OS browser, and only for http/https.

Compatibility without carrying the past

The app and its Python runtime update on separate clocks. Keep fallbacks narrow, tied to an identified older runtime, and tested (the serve → dashboard fallback is the model).

Respect the user

Never navigate or steal focus because something happened in the background. Empty, loading, reconnecting, degraded and exhausted states each get their own copy and way out. Expensive surfaces stay alive when hidden.

Make it feel instant

Hot-path state local; don't subscribe heavy trees to per-frame updates; coalesce pointer work; don't read layout right after writing style. Prove speed on a long transcript, not an empty demo.
