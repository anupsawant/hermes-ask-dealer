Architecture & Onboarding Guide

Local Install vs Gateway

When you first install and launch the Gideon / Hermes Desktop app, you are given a fundamental choice: run Gideon locally on your computer, or connect to an existing Gateway. Here is exactly what the Gateway is, how both fresh install processes work under the hood, and how tool execution, state, and resources differ.

Electron 40.10.2 FastAPI & JSON-RPC 2.0 DesktopInstallOverlay FirstRunRemoteSetup connections.json

01What is the Gateway?

In the Hermes Agent ecosystem, the Gateway (represented by hermes serve and gateway/run.py) is the headless backend daemon and control plane that executes the AI agent.

The Desktop application (Gideon) does not embed Python or run the LLM inference loop directly inside Electron or React. Instead, Desktop is an Electron + React 19 client that connects to a running Gateway instance over HTTP and a full-duplex WebSocket speaking JSON-RPC 2.0.

Responsibilities of the Gateway

1. Turn Loop & Context

Maintains conversation state, system prompt building, prefix caching (sacred invariant), token budgets, context compression, and LLM provider handshakes.

2. Tool Execution Engine

Executes shell commands in a real terminal, reads/writes filesystem assets, drives headless browser sessions via Playwright, runs skills, and fires background jobs.

3. Multi-Platform Connectivity

A Gateway instance can simultaneously connect to Discord, Telegram, Slack, and WhatsApp while simultaneously serving the Desktop app over WebSocket.

4. 24/7 Persistent Storage

Holds the SQLite database (hermes_state.db), cron scheduler schedules, long-term memory, and workspace artifacts even when the desktop client is closed.

Key Architectural Insight

A "Local Install" simply spawns a private Gateway on 127.0.0.1 managed as a child process by Electron. Connecting to an "Existing Gateway" points Desktop to an external Gateway running on a remote cloud server, homelab, VPS, or another machine on your local network (LAN / Tailscale).

02The First-Run Fork: What Happens on Fresh Launch

When you download and launch Gideon Desktop on a clean machine for the very first time, the application runs a detection gate:

  1. Probe Existing Connections & Runtimes
    Electron checks connections.json in the app's user data directory (app.getPath('userData')). On a fresh install, this file does not exist or has no active connections.
  2. Probe Local Hermes Backend (resolveHermesBackend)
    Electron looks for an existing Python venv, a global hermes CLI executable in PATH, or bundled binary. If nothing is found, it returns { kind: 'bootstrap-needed' }.
  3. FirstRunSetupGate Latches Open
    Because no local runtime exists and no remote connection is saved, getFirstRunSetupGate().shouldGate(backend) returns true. The boot sequence pauses at progress 12%: "Waiting for first-run setup choice".
  4. DesktopMounts Setup Choice Overlay
    The renderer displays DesktopInstallOverlay with two large interactive cards.

03Path A: Detailed Breakdown of Local Install

When the user clicks "Install Gideon locally" (or "Use Gideon on this computer"), they instruct the app to provision an entire local execution stack on their machine.

1. Automated Bootstrap Pipeline

Electron starts the platform bootstrap runner (e.g. install.ps1 on Windows, or automated scripts on macOS/Linux) and communicates over a JSON line streaming protocol:

Stage NameAction Taken on HostTypical Duration
system-packagesVerifies C++ build tools, system libraries, and OS prerequisites.1s – 5s
gitVerifies Git is installed or downloads a portable Git binary for version control and skills fetching.1s – 8s
pythonFinds or downloads an isolated Python 3.11/3.12 runtime.5s – 30s
uvProvisions uv (Astral's high-speed package manager) to manage virtual environments.2s – 10s
environmentCreates an isolated virtual environment in ~/.hermes/env (or custom HERMES_HOME).3s – 15s
dependenciesDownloads and installs hermes-agent, FastAPI, Uvicorn, SQLite, Playwright, and agent toolsets.20s – 90s

The UI renders live progress via StageRow components with status icons (Done, Installing, Failed), live millisecond timers, and an expandable raw terminal output drawer.

2. Spawning the Local Subprocess

Once bootstrap completes, Electron's spawnHermesBackend() in electron/main.ts starts the backend:

// Spawning hermes serve locally
const child = spawn(pythonExe, [
  '-m', 'hermes_cli.main', 'serve',
  '--port', String(allocatedPort),
  '--listen', '127.0.0.1',
  '--session-token', generatedToken
], {
  cwd: hermesHome,
  env: { ...process.env, HERMES_HOME: hermesHome }
});
  • Port Allocation: Dynamically allocates a free TCP loopback port (e.g., 127.0.0.1:54321).
  • Token Generation: Generates a random session token stored in local memory and passed to the child.
  • READY Line Detection: Electron scans the child's stdout for the line READY http://127.0.0.1:PORT to confirm server readiness.
  • Process Binding: The child process is tied to Electron's lifecycle. When you quit Gideon Desktop, the local hermes serve process is terminated with SIGTERM.

3. Socket Handshake & Post-Install Onboarding

Once the local server answers the health probe:

  • The React renderer connects its WebSocket client: ws://127.0.0.1:54321/api/ws?token=...
  • DesktopInstallOverlay fades out.
  • The DesktopOnboardingOverlay (or AskDealerGate) mounts:
    • Prompts user to configure API keys (Nous Research / Ask Dealer portal, OpenAI, Anthropic, or local Ollama).
    • Prompts for persona, bot name, and default tool permissions.
    • Saves settings to local ~/.hermes/config.yaml and secrets to ~/.hermes/.env.
  • Main chat interface unlocks.

04Path B: Detailed Breakdown of Gateway Connection

When the user clicks "Connect to existing Gideon" (Gateway Mode), they bypass local installation entirely. The desktop app transitions into a pure thin client.

  1. Mount FirstRunRemoteSetup
    The overlay switches from the dual-card view to FirstRunRemoteSetup (managed by useRemoteSetup({ host: 'first-run' })).
  2. Enter Gateway URL & Live Probe
    The user inputs a Gateway URL (e.g., https://hermes.mycompany.internal, http://192.168.1.150:8000, or a Tailscale IP). As the user types, useRemoteProbe sends an HTTP GET /api/status to test reachability.
  3. Authentication Classification
    The gateway inspects the response to determine authentication requirements:
    • auth_required: false → No credentials needed (trusted local network).
    • auth_required: true with OAuth → The gateway advertises an identity provider (Google, GitHub, Authentik). Gideon shows a "Sign in with [Provider]" button. Clicking it opens a secure Electron browser popup, performs the OAuth flow, and captures hermes_session_at and hermes_session_rt session cookies.
    • auth_required: true with Session Token → Prompts for the bearer token from the remote server's .env file.
  4. Preflight Verification (Test Connection)
    Before writing anything to disk, the user clicks "Test connection". Electron performs two preflight checks:
    1. Authenticated REST request to /api/status.
    2. Mints a single-use ticket via POST /api/auth/ws-ticket and completes a real WebSocket handshake to wss://.../api/ws?ticket=....
    Only if both pass does the "Apply and reconnect" button enable.
  5. Atomic Application (applyConnectionConfigAtomically)
    When the user clicks "Apply and reconnect":
    • abandonFirstRunSetupChoiceForRemoteApply() releases the bootstrap waiter and dismisses the install overlay.
    • teardownPrimaryBackendAndWait() kills any local Python backend process that was running, releasing local CPU and memory.
    • Writes the remote configuration into connections.json in userData: 
      {
  "primary": "conn-remote-1",
  "connections": [
    {
      "id": "conn-remote-1",
      "kind": "remote",
      "label": "Production Cloud Gateway",
      "baseUrl": "https://hermes.example.com",
      "authMode": "oauth",
      "createdAt": 1728950000000
    }
  ]
}
    • The renderer re-homes: wipes gateway-bound stores and connects the JSON-RPC WebSocket directly to the remote URL.

06Where Code & Tools Run (The Execution Boundary)

The most important concept to understand when choosing between Local and Gateway is the Tool Execution Boundary. Consider what happens when you ask the agent:

"Search my git repository, run pytest, and update the dependencies in pyproject.toml"

Under Local Install:

  • terminal("pytest") runs inside your local terminal shell on your laptop.
  • Files modified by write_to_file are edited on your local hard drive.
  • If the agent creates files, they appear in your local directory.
  • If the command crashes or eats CPU, it impacts your laptop's battery and fan speed.

Under Gateway (Remote):

  • terminal("pytest") runs inside the remote server's terminal (or container).
  • Files modified by write_to_file are edited on the remote server's filesystem.
  • No files on your local laptop are modified unless you explicitly sync them (e.g. git push/pull).
  • Heavy builds, test suites, and Docker tasks run on the server's CPU/RAM, leaving your laptop cool and quiet.

08Which Should You Choose?

Choose Local Install if:

  • You want the agent to directly manipulate your local files, codebases, and desktop apps.
  • You are running on a powerful machine with ample disk space and RAM.
  • You want the option to work offline using local models (e.g., Ollama).
  • You do not have a dedicated server, VPS, or cloud instance already running Hermes.
  • You only plan to use Hermes on this specific computer.

Choose Gateway (Remote) if:

  • You have a remote server, VPS, Homelab (Mac Studio, Unraid, TrueNAS), or cloud cluster running Hermes.
  • You are on a lightweight laptop (e.g. MacBook Air) and want to conserve battery, disk space, and RAM.
  • You want 24/7 background tasks, scheduled cron runs, and continuous Telegram/Discord bots.
  • You want to access the exact same agent sessions seamlessly from multiple laptops, PCs, or web browsers.
  • You prefer centralized management of API keys, model endpoints, and shared databases.
Switching Later

This choice is never permanent. You can switch back and forth at any time inside Gideon Desktop by opening Settings (⌘,) → Gateway or Connections. Switching connections takes only 2 seconds and simply re-homes the WebSocket without needing to reinstall the app.
